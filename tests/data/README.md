# RTG 500 Regression Fixtures

- `sample.input.txt`: 50 Moses-tokenized source sentences, in fixed random order.
- `sample.input.lang.txt`: aligned tab-separated FLORES language code and
  one-based `devtest` row number, without a header.
- `sample.eng.rtg-500eng-v1.expect.txt`: baseline model translations, not human
  reference translations. Do not edit these to make a failing regression pass.
- `sample.eng.rtg-500eng-v1.out.txt`: generated by `make test`, ignored by Git.

All files have one entry per sentence and retain the same order. Five examples
come from each language: French, German, Spanish, Portuguese, Italian, Russian,
Modern Standard Arabic, Hindi, Swahili, and Turkish.

## Sampling and Attribution

Source: [FLORES-200](https://github.com/facebookresearch/flores/tree/main/flores200),
NLLB Team (2022), `devtest` split (1,012 sentences per language).
The [original archive](https://dl.fbaipublicfiles.com/nllb/flores200_dataset.tar.gz)
has SHA-256 `b8b0b76783024b85797e5cc75064eb83fc5288b41e9654dabc7be6ae944011f6`.

The FLORES-derived source and translation fixtures are distributed under
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/), following the
[upstream dataset license](https://huggingface.co/datasets/facebook/flores).
Changes are sampling, punctuation normalization, Moses tokenization, and
machine translation. This notice applies to the fixture data, not Kidi source code.
See NLLB Team, [No Language Left Behind: Scaling Human-Centered Machine Translation](https://arxiv.org/abs/2207.04672).

Sampling used Python 3.9, `random.Random(20260920)`, and this language order:

```text
fra_Latn deu_Latn spa_Latn por_Latn ita_Latn
rus_Cyrl arb_Arab hin_Deva swh_Latn tur_Latn
```

For each language, build candidates in source-file order with 40-200 Unicode
characters and a row ID not already selected for another language. Select five
with `rng.sample(candidates, 5)`, then shuffle all 50 with the same RNG. Thus
each sentence ID is unique across the fixture. The recorded row IDs allow the
original sentences and article metadata to be recovered from the archive.

Preprocessing used `sacremoses-xt==0.0.44`: `MosesPunctNormalizer(lang).normalize`
followed by `MosesTokenizer(lang).tokenize` with `aggressive_dash_splits=True`,
`return_str=True`, and `escape=False`. The corresponding Moses codes, in the
same order, are `fr de es pt it ru ar hi sw tr`. The test uses the already
tokenized fixture and does not download FLORES or require Sacremoses.

## Baseline and Acceptance

The golden output was generated on 2026-09-20 using the independently saved
pre-pruning eager Kidi release binary (SHA-256
`49fde6606a7da05b37432498d3bb4498877e6236bbab7122fb92bbf0586a1c32`), on Apple M5
with macOS 26.6.2. It uses the BF16 Hub model at revision
`e166c18be310898939569a50a23d7de2c9ccf9ed`.
The runner now pins `8581803b79d7ab3f46697140788272e3417bb238`, with deduplicated
BF16 weights and nested model/decode YAML. Token IDs and weight dtypes come from
the tokenizer/checkpoint files; decoding settings are defaults, not caps.
The expected translations are unchanged; both CPU and Metal match
all 50 sentences. The original PyTorch RTG FP32 implementation also matches
these expected translations exactly.
This is a behavior regression test; baseline translation errors are intentionally
preserved, and a high score does not establish multilingual translation quality.

Decoding settings: YNNPACK CPU, eight threads, greedy beam one, batch/window one,
50 maximum extra tokens, and length penalty 0.6. Expected translations are kept
in Moses-tokenized form. The model is downloaded and checksum-verified by
`make setup-test`, not stored in this repository.

Scoring uses SacreBLEU 2.6.0 corpus chrF2: character order 6, word order 0,
beta 2, case-sensitive, whitespace excluded, effective order enabled. The
default minimum is 99.0/100, allowing small numerical differences between
backends; line-count mismatches and blank outputs always fail. Scores below the
threshold produce a nonzero exit code and leave the output file for inspection.

To tighten the check, run `make test MIN_CHRF=100`. Inspect any output differences
before deliberately updating the expected file or pinned model revision. Neither
setup nor regression execution overwrites the expected output.
